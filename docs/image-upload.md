# 이미지 업로드와 자동 레이블링

1. 워크스페이스를 열고 **이미지 업로드**를 선택합니다. 목록 화면에서도 업로드할 워크스페이스를 고를 수 있습니다.
2. 이미지 파일과 데이터 구분을 선택합니다. 기본값은 **미지정**이며 운영 데이터의 용도를 미리 정하지 않고 받을 수 있습니다. 카테고리를 미리 지정하지 않고 서로 다른 상품 이미지를 함께 올릴 수 있습니다.
3. 업로드한 이미지는 워크스페이스의 기존 이미지 목록에 **미레이블** 상태로 추가됩니다. 기존 이미지와 레이블은 유지합니다.
4. **자동 레이블링**에서 기본 Qwen 모델, 현재 데이터와 같은 레이블 형식으로 학습한 모델 또는 Gemma-4-12B를 선택합니다. 보관됐거나 파일이 없는 모델은 선택할 수 없습니다.
5. 접수된 작업은 기존 GPU 큐에서 순서대로 실행됩니다. 워크스페이스에 진행 상태가 표시되며 학습 모니터링 화면에서 로그와 취소 기능을 사용할 수 있습니다.
6. 비케이브 형식에서 카테고리가 없는 이미지는 모델이 카테고리와 속성을 함께 판별합니다. 판별한 카테고리의 허용값으로 검증하고, 카테고리 판별에 실패한 이미지는 미레이블로 남깁니다. 수동 검토 시에는 이미지별 카테고리를 지정할 수 있습니다. 원본 `visual-v1` 데이터는 기존 14개 속성 사전으로 판독합니다.

업로드와 자동 레이블링은 현재 데이터의 레이블 형식을 유지합니다. 원본을 비케이브 형식으로 자동 변환하지 않습니다. 자동 레이블링은 사용자가 시작한 뒤 새 버전에 반영하며 이전 원본은 보존합니다. 새 워크스페이스의 첫 업로드는 비케이브 형식을 사용합니다.

자동 레이블은 사람 검증 정답이 아닙니다. 허용값에 없는 출력과 미확인 속성은 제외하고 원문을 보존합니다. 전부 해석하지 못한 이미지는 미레이블 상태로 남습니다. 미레이블 이미지가 남아 있는 데이터셋은 학습, 평가, 데이터 재구성과 드리프트 비교에 사용할 수 없습니다. 먼저 자동 레이블링을 다시 수행하거나 수동 레이블을 작성하세요.

## 파일과 저장 방식

- JPEG, PNG, WebP 단일 이미지. 파일당 20MB, 전체 100MB, 한 번에 최대 200개, 최대 2,500만 화소.
- ZIP이나 레이블 파일이 필요하지 않습니다. 파일 선택과 드래그 앤 드롭을 지원합니다.
- 현재 워크스페이스에 같은 이미지 해시가 있으면 추가하지 않습니다. 중복 업로드는 기존 레이블, 카테고리와 분할을 덮어쓰지 않습니다.
- 모든 이미지 검증이 끝난 뒤 저장합니다. 잘못된 파일이 있으면 해당 업로드 전체를 반영하지 않습니다.
- 이미지 파일은 `.runtime/uploads/`에 보관하고, SQLite에 파일 경로, 해시, 카테고리, 분할, 레이블과 모델 출처를 저장합니다. DB만 백업하면 이미지 파일은 복구되지 않습니다.
- 미레이블 여부는 모델이 예측한 속성값과 별도로 기록합니다. `unknown`을 정답으로 만들어 학습시키지 않습니다.

## API

`POST /api/workspaces/{workspace_id}/images?name=...&split=train`

`category`는 선택 항목이며 기존 API 호출에서 명시한 값은 유지합니다.
운영 유입 데이터는 `split=unassigned`로 보냅니다. 화면에서는 이 값을 기본으로 사용하며,
기존 API의 분할 생략 시 기본값 `train`은 호환성을 위해 유지합니다.

`multipart/form-data`의 `files` 항목에 이미지들을 반복해 첨부합니다. 성공 시 `dataset`, `duplicate`, `skipped_duplicates`, `added_count`를 반환합니다. 예:

```sh
curl -F 'files=@shirt-a.jpg' -F 'files=@shirt-b.jpg' \
  'http://121.126.210.3:18091/api/workspaces/WORKSPACE_ID/images?name=shirts&split=train'
```

`GET /api/labeling-models?schema_id=...`에서 데이터 형식과 호환되는 모델 목록을 조회하고 `POST /api/jobs`에 다음을 전달합니다. 형식을 생략하면 비케이브 형식이며, 원본 형식은 `schema_id=visual-v1`입니다. 기본 모델은 두 형식에서 사용할 수 있고, LoRA는 학습한 형식과 일치해야 합니다.

```json
{"kind":"labeling","dataset_id":"DATASET_ID","model_id":"MODEL_ID"}
```

기본 Qwen 모델 ID는 `qwen35_2b`, `qwen35_4b`입니다. 학습 모델은 레지스트리에 등록된 실제 ID를 사용합니다. Gemma는 `gemma4_teacher`입니다. 기존 `model_id` 없는 레이블링 요청도 Gemma를 사용하도록 호환성을 유지합니다. 동일 데이터셋의 레이블링이 진행 중이면 새 요청은 409를 반환합니다.

작업 완료 시 `result.applied_count`는 현재 이미지에 반영한 수, `skipped_changed_count`는 작업 중 삭제되거나 수정되어 덮어쓰지 않은 수입니다. 새로 업로드한 이미지는 진행 중이던 판독의 입력에 없으므로 미레이블 상태로 유지됩니다. 학습 모델을 선택하면 해당 LoRA 어댑터를 실제로 불러와 추론합니다.

## 워크스페이스의 이미지와 레이블

이미지 카드의 위쪽 이미지 영역은 선택·해제, 아래쪽 상태 영역은 레이블 검토에 사용합니다.
상세 상단은 파일명을 표시하며 업로드 파일명 또는 원본 이미지의 파일명을 사용합니다.
미레이블 이미지는 `레이블링 대기`, 자동 레이블링 후에는 `자동 레이블링 완료`와 `검토 대기`,
사람이 검토하고 저장한 이미지는 `검토 완료`로 표시합니다. 카드 하단과 상세에서 같은 기준을 사용하며
모델 설정만으로 자동 레이블링 완료 상태를 표시하지 않습니다.
검토 완료 이미지는 상세 하단의 `검토 취소`로 검토 상태만 되돌릴 수 있습니다. 레이블 값과 분할은 유지하고
수정 이력에 취소 시각을 남깁니다. API는 `DELETE /api/datasets/{id}/samples/{sample_id}/review`입니다.
두 초기 import의 모델 표기는 사용자 정정에 따라 GPT-Astra를 사용합니다. 저장된 출처 문자열과
불변 원본은 보존하고, 최초 작업의 실제 시각이 없는 경우 날짜를 임의로 만들지 않습니다.

워크스페이스마다 현재 이미지 목록 하나만 제공합니다. 버전 선택, 변경 이력, 이전 데이터 복귀 기능은 없습니다. 수동 레이블 저장, 업로드, AI 결과 반영, 삭제와 복원 모두 이 목록에 반영됩니다. 수동 편집창을 열어 둔 동안에는 입력을 유지하고, 같은 이미지의 레이블이 다른 작업에서 먼저 변경되면 저장을 409로 차단하여 재확인하도록 합니다.

`GET /api/datasets?current=true`와 `GET /api/workspaces`는 워크스페이스별 현재 데이터만 반환합니다. SQLite `workspace_data`가 현재 데이터 ID를 지정합니다. 빈 데이터로 만든 워크스페이스는 서버 재시작 후에도 빈 상태를 유지합니다. 기존 내부 데이터 API와 완료 작업의 입력 ID는 호환성을 유지하지만 화면에서 이전 레이블을 선택하는 용도로 제공하지 않습니다.

학습 입력 재현을 위한 불변 데이터는 내부에 남습니다. 처음 적용할 때 기존 워크스페이스에서 가장 최근에 저장된 데이터를 현재 목록으로 지정하며, 기존 모델·작업·이미지·레이블 본문은 다시 작성하지 않습니다.
